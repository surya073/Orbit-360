# Company 360 (orbit360)

Internal analytics/reporting app on Zoho Catalyst. Project `orbit360` (id 46135000000311001), Development env, timezone Asia/Kolkata.

## Layout
- `functions/orbit_funtion/` - the only backend: Advanced I/O function, `node22`, raw `(req, res)` handler (no Express, no listening server). The folder name is intentionally spelled `orbit_funtion`; do not rename it or add another function.
- `orbit-web/` - React 19 + CRA (`react-scripts` 5), hash routing, JavaScript. Own `.git` repo.
- `data/` - schema source of truth (`database-schema.md`, `company360.schema.json`). 22 Data Store tables already exist. Never recreate tables, rename them or reinitialize Catalyst.

## Commands
- Backend tests: `cd functions/orbit_funtion && npm test` (node:test; runs the real app against an in-memory Catalyst SDK fake in `src/tests/helpers`)
- Frontend tests: `cd orbit-web && CI=true npx react-scripts test --watchAll=false`
- Frontend build: `cd orbit-web && CI=true npm run build` (CI=true makes lint warnings fail)
- Run locally with `catalyst serve` only (needs Node 22 configured: `catalyst config:set node22.bin=<path>`; local Node is 20, so it has not been run here). Never the bare dev server: it lacks `/__catalyst/sdk/init.js`, so auth fails. Serve and test locally before `catalyst deploy --only functions:orbit_funtion -ni`.
- Frontend-only work with no Catalyst requests: `cd orbit-web && npm run start:local` (fake sign-in + sample API from `scripts/dev-stub.js`, wired by `src/setupProxy.js` only when LOCAL_STUB is set; `STUB_ROLE=manager` previews a manager, `STUB_TABLES=0` the "access tables missing" state). Writes are accepted but not stored; it does not test the real backend or auth.
- Do not call the bash tool with very large multi-file heredocs; use Write for files.

## Backend (`functions/orbit_funtion`)
Request flow (`src/app.js`): context -> route match -> authenticate -> authorize (builds Scope) -> read body -> validate -> controller -> service -> repository. API base `/server/orbit_funtion/api/v1`; `GET /health` is the only public route.
- `config/`: `environment.js` (env vars, clamped), `constants.js` (limits, roles, completeness values), `datastore.js` (budgeted SDK wrapper), `resources.js` (registry of exposed tables: list columns, team column, filters, writable field specs).
- `routes/` (thin, declarative) -> `controllers/` (HTTP adapters) -> `services/` (business rules) -> `repositories/` (the only place SQL is built). Controllers never touch the database.
- Access & permissions: a permission is `<module>.<action>` (`employees.edit`); the catalog (modules, actions, default Manager set) lives in `config/permissions.js`. `middleware/authentication.js` resolves the caller's role through `services/accessResolver.js` (tables `user_roles` -> `roles` -> `role_permissions`, falling back to the built-in `admin`/`manager` roles when those tables are missing or hold no row) and puts `permissions` + `scopeType` on the actor. **Default-deny:** every non-public route must declare `permission: 'x.y'` (or an array that must ALL be held) or `open: true`; `crudRoutes` derives view/create/edit/delete from the resource's module; services re-check (`requirePermission`, `services/crud.service.js`). A role's `scope_type` (`all_teams`/`own_team`) decides team scope (`Scope.isAdmin` now means "sees every team"). `services/access.service.js` + `routes/access.routes.js` manage roles/users with escalation rules (cannot grant what you lack, cannot change yourself, only an Administrator changes an Administrator, Administrator role is protected, last admin kept). Schema to create by hand: `data/access-permissions-schema.md`. The old application-settings screen and API are gone; the `application_settings` TABLE stays (the reporting tree uses it).
- People & invitations: `POST /access/invitations` (services/access.service.js `inviteUser`) calls Catalyst `userManagement().registerUser` (via `ctx.auth`, admin scope; Catalyst emails the link, the person sets a password on Catalyst's page and signs in through the embedded login) then creates the `users` + `user_roles` rows. Per-person overrides live in table `user_permissions` (allow/deny/inherit; effective = role + allow - deny; Administrators ignore them; `accessResolver` loads them, so sign-in costs one more Data Store query per cache miss; optional table, roles keep working without it). `GET/PUT /access/users/:id/permissions`. UI: Access -> Users tab (`InviteModal`, `UserPermissionsModal`). `classifyDbError` checks the schema pattern before the permission pattern because table names contain "permission".
- Security boundary: `middleware/authentication.js` maps the Catalyst session to a `users` row (role + team). `services/scope.service.js` `requireScope()` returns a `Scope`; repositories REQUIRE one (`assertScope`) and apply team conditions themselves. Out-of-scope rows return 404 (no IDOR/existence leak). Never accept role/team from the client; team columns are derived server-side (`services/recordRules.js`).
- Cost controls: Data Store is billed per request. `config/datastore.js` enforces a per-request query budget (`QUERY_BUDGET`, imports get more); lists cost 2 queries; dashboard = grouped aggregates only; references are loaded with one `ROWID IN (...)` query per parent table (no N+1); `LIMITS.maxPageSize` 100, trends max 90 days, IN lists chunked at 50. Never page through a whole table.
- Function invocations (the Catalyst plan allows about 2000, and every API request is one): the dashboard loads through ONE request, `GET /dashboard/bundle` (six sections, each `{ok,data}` or `{ok:false,error}`; own budget 40), not six; presentations still use the per-section endpoints because a slide fetches only what it shows. `apiClient` shares identical in-flight reads (even abortable ones), caches reads (60 s; teams, templates and access catalog/roles 10 min; `/dashboard/*` 3 min) and retries a transient read failure once; any write clears the cache. Dashboard filter changes are debounced 450 ms (`useDashboardData`), and a custom range is applied once, when its end day is chosen. Spreadsheet saves cost one request per edited record (the API has no bulk update); imports cost one per 100 rows. Before adding a call, check it is not already served by the bundle or the cache.
- Metrics (`services/metrics.service.js`): only approved, non-deleted time entries count, read from `time_entries` alone (never joined to assignments or multiplied by headcount). Every metric has `completeness`: `complete | partial | insufficient_data | not_applicable`; missing data is `null`, never 0. Late status is only the stored `late_status` (no invented cutoff).
- Imports (`services/import.service.js`): job -> preview batches -> resolve conflicts -> commit batches -> complete. Max `IMPORT_BATCH_SIZE` (100) rows per call; the client keeps the file and resends batches. Idempotent via `import_rows` status, unique `dedupe_key`/source ids, and `import_job_id` on target rows. Imported time entries stay `pending`.
- Data Store quirks: ZCQL rows are wrapped under the table name; max 300 rows / 20 columns per SELECT; booleans are the strings `"true"`/`"false"`; strip 4-byte emoji; create rows with `is_deleted: 'false'`. ZCQL `LIKE` wildcards are `*` and `?`, never SQL's `%` (a `%` matches literally, so search returns nothing); build text search only through `queryBuilder.likeVariants`. Only validated ids/dates/enums are interpolated into ZCQL (`queryBuilder.lit`).
- Errors/logging: `utils/errors.js` (`ApiError`, `classifyDbError`), `middleware/errorHandler.js`. Logs are structured JSON with `requestId`; `utils/logger.js` redacts personal fields and error messages/stack headers are never logged (they can contain row values).
- Extra columns (`custom_fields` table, `services/customFields.service.js`): definitions per module; values live in the row's `more_details`. CRUD create/update validate `more_details` (defined keys are type-checked, other keys are refused unless the stored row already holds the same value, so imports survive edits; 2000 chars max for defined values). Definitions are cached 10 min per instance. `GET <list>?extra=1` adds `more_details` to list rows (no extra request). Permission module `custom_fields` (managers: view only). Frontend: `hooks/useCustomFields` (cached, skipped without `custom_fields.view`), spreadsheet columns `x:<key>` built in `gridModel.js`, `CustomColumnsDialog` (no longer opened from the toolbar: rows and columns are added by typing into the blank sheet). Not yet in forms or CSV import.
- Add a table: register it in `config/resources.js`, add a `routes/*.routes.js` using `crudRoutes`, add tests.

## Frontend (orbit-web/src, plain .js, CRA)
- app/ (App, providers: Auth/Theme, routes + guards), components/{layout,navigation,cards,charts,tables,forms,filters,feedback,common}, config/ (navigation, themes, constants, routes, env, features), features/<module>/, hooks/, services/ (apiClient + one service per feature), utils/, styles/{tokens,themes,global,components,layout,controls,settings}.css, tests/.
- Cards and inline styles: ALL card looks live in `styles/cards.css` (raised soft cards after `UI_Design/4120f45f...jpg`: a small icon level with the label, a big number, a coloured right-edge notch, kept short; the employee profile card `.hcard` follows `UI_Design/fd6ea0d4...jpg`; families `.card`, `.kpi`, `.hcard`, `.rs-promo`; every size/radius/colour is a variable on `:root` at the top, so tune it live in Chrome DevTools). It is imported after the older sheets on purpose; do not add card looks to bento.css/module.css/signature.css. Spacing helpers (`u-mt-3`, `u-mb-4`, ...) and the classes that replaced inline `style={{}}` live in `styles/utilities.css`. Inline `style` is only for run-time values (chart geometry, data/theme colours, tour spotlight, virtual-scroll heights); put anything static in a stylesheet.
- Design system: tokens.css (type scale, spacing, motion) + themes.css (7 hand-made themes via [data-theme]: ember (default; warm-black glass, also supplies --panel-*/--promo-*/--rail-bg tokens, defaults in tokens.css), blueberry, blackcurrant, volcano, sunset, ocean, forest) plus themes.extra.css (22 more, 11 dark and 11 light, GENERATED from seed colours by `npm run gen:themes`, which also writes config/extraThemes.json and the id list in public/index.html; never edit that CSS by hand); old ids light/dark/moon/beach migrate in ThemeProvider and index.html; run `npm run gen:login-css` after color or theme changes, no hardcoded colors in components). Fonts are self-hosted (@fontsource-variable DM Sans + Manrope) with system fallbacks. src/tests/themes.test.js verifies WCAG contrast for every theme: change a color, run it.
- Controls/DnD: use forms/Field + forms/Choice (Checkbox/Radio/Switch); reorderable lists use components/common/SortableList (@dnd-kit; drag handle + keyboard + move buttons). Dashboard widget order/visibility persists per device in localStorage `company360.dashboardLayout` (config/dashboardLayout.js, hooks/useDashboardLayout).
- Spreadsheet editor (`features/spreadsheet/`, route /spreadsheet, third data-entry option next to Add form and Sheet import via DataEntryModes): columns come from GET /imports/templates, data through resourceService (list/create/update/remove); only changed fields are PATCHed, saves are bounded-concurrency with a pre-save field-level conflict check (list has no MODIFIEDTIME), saved values cannot be cleared (API omits blanks), schema is fixed so no add-column. gridModel.js is pure (incl. jumpTarget/rangeLabel); useSheetData owns edits/undo/save (the pre-save conflict check passes `{ fresh: true }` so it never reads the apiClient cache); SheetGrid owns selection/keyboard/clipboard/context menu and exposes copy/cut/paste/clear via ref; SheetToolbar + SheetShortcuts are presentational. The /spreadsheet route is a full-height workspace (AppShell adds `shell--workspace`; the grid flexes, no fixed heights). Search has two scopes: server (name, debounced, resets to page 1) and loaded rows (all columns). Ctrl/Cmd+F and Ctrl/Cmd+S are handled only while focus is inside the sheet. Column widths and row density persist per device in localStorage. The tool row (`SheetFormatBar.js`, Google Sheets layout: search, undo/redo, print, paint format, zoom, £/%/decimals/123, font, size, B/I/S, colours, borders, align, wrap, link, note, filter + saved filter views, functions) uses spreadsheet-only glyphs from `SheetGlyph.js`; formatting (incl. number formats, borders, notes) is device-local, never sent to the API. Merge, rotate and chart are shown disabled with the reason in the tooltip.
- Import mapping (`utils/headerMatch.js`, `features/imports/ImportPage.js`): headers are matched to template fields in the browser by exact name, a synonym/abbreviation table, spelling similarity (Jaro-Winkler) and what the values look like (dates, emails, enum values). Each match is `high` (shown no panel when every required field is high) or `medium` (the mapping panel opens pre-filled with Matched/Check badges, a tray of unmatched fields to drag onto a column, and Reset). A confirmed mapping is remembered per module + header row in localStorage `company360.importMaps`. `more_details` is never guessed. The module page's Import and Spreadsheet buttons open `/imports?module=` and `/spreadsheet?module=` with the type already chosen. No AI call: nothing about the file leaves the browser.
- Spreadsheet saving: Save is manual by default. View -> Autosave (per device, `company360.sheetAutosave`, off by default) saves edits to EXISTING records ~3 s after typing stops, in one batch; new rows, flagged conflicts/errors and a failed attempt always wait for Save. Unsaved edits are mirrored to sessionStorage `company360.sheetDraft.<resource>` (gone when the tab closes, never left on a shared PC) and offered back with Restore/Discard. Clicking a column header never scrolls the grid (it selects the whole column); blank columns show "+ Add column".
- Presentation sharpness: `.pres__canvas` is scaled with a plain `translate(px) scale()` (whole-pixel offsets, no `perspective`, no `will-change`); the flip transitions carry their own `perspective()`. Putting perspective or a 3D context on the canvas makes the browser upscale a 1920x1080 raster (blurry text).
- Access: roles are changed right in the Users table (`RoleCell`, applied at once with an Undo toast; toasts accept `{ action: { label, onClick } }`), Edit access saves in one step (only blocking someone adds a review), the invite dialog uses role cards with "Send and add another" and "fine-tune permissions", and the individual-permissions matrix has per-module "allow all / follow role" and "Reset to the role".
- Presentation studio (`features/presentations/studio/`, routes `/presentations/new` start page, `/presentations/studio` new deck, `/presentations/:id/edit` editor, `/presentations/quick` = the old sections-only builder): a deck is a list of slides; a `custom` slide is free-form (background + up to 40 objects on a 1920x1080 canvas: text, shapes, pictures, link buttons, live-data widgets) and a `section` slide is a live report drawn by the player. `slideModel.js` is the pure model, `SlideCanvas.js` draws a slide for the editor, thumbnails and player (three layers per object: box, entrance animation, hover effect), `Stage.js` is the editing layer (drag, resize, snapping guides, inline text edit), `Inspector.js` the panels, `useDeckHistory.js` undo/redo (gestures merge by key), `templates.js` the six designs (flat colours, no glow/orbs/dot grids; fixed hex colours), `pptxImport.js` reads a .pptx in the browser with `fflate` (text, shapes, pictures, theme colours, groups; pictures are shrunk to a small budget, tables/charts are reported as not imported; no AI call), `userTemplates.js` keeps "Your templates" on this device (localStorage), `widgetData.js` + `WidgetView.js` the live widgets (big number with change on the previous period, ranked bars, donut, trend, leaderboard) fed by the same backend metrics as the dashboard (`/dashboard/highlights` for people lists); a deck fetches only the datasets its widgets use. Theme and slide transition are chosen on the start page (stored per device, stamped on each new slide) and per slide in the editor's Slide panel (`LookPicker`, with "use on every slide" and "animate everything"); a custom slide carries optional `theme` and `transition` (whitelisted in `slideSchema.js`), the player applies them per slide until the viewer picks one in its own menus. Animations can start "with the slide" or "on click N": in the player Next reveals the next group before changing slide. A deck with a custom slide is exactly what its author built: no generated cover/closing, no story templates, no added people/records/reporting slides, and Play skips the launcher. The player draws no drifting orbs, rings or dot grids any more.
- Studio storage: backend `validators/slideSchema.js` rebuilds every custom slide from a whitelist (colours hex/theme keywords, https or small inline raster pictures only, links http(s)/mailto/#slide-N); `presentation.service.js` stores `slides_config` as JSON, or as `z1:` + base64(deflate) when it does not fit the 9,000-character column. Pictures uploaded in the editor are shrunk to about 14,000 characters (logos, icons); photos should be links. A File Store folder would lift this (not set up).
- Dashboard highlights: the bundle has a 7th section `highlights` (top performers by approved hours, best on-time attendance, new joiners in the last 30 days; run AFTER the other six because the Data Store throttles a burst of parallel queries). `features/dashboard/signature/Highlights.js` is the auto-advancing card (hover/focus pauses, dots jump, reduced motion never moves by itself); it replaces the old "needs attention" button card and shows the warnings as a last slide.
- One presentations module: `PresentationsPage.js` keeps the presentation-center layout (hero, preview cards, launcher; styles in `styles/presentationCenter.css`). The backend list derives `cover`, `slideCount`, `studio`, `unreadable` from `slides_config` (it never returns the config): a studio deck's card shows its real first slide and Present plays it at once, a report deck still opens the launcher (theme, layout, story); Edit opens the studio, Duplicate/Delete are on the card. A deck whose slides cannot be decoded says why (`slidesProblem`) in the player and on its card. The local stub keeps presentations in memory so the whole flow can be tried without Catalyst. Anything that needs AI uses `components/common/AiButton` and `config/features.js` `aiAssist` (false): the button explains that AI is not connected instead of doing nothing; PowerPoint import extracts text, shapes, pictures, entrance animations/click steps, theme colours (offered in every colour picker), fonts and layout names with built-in rules and shows a summary with warnings. The page-scroll lock only sets `overflow:hidden` on `<html>` (never fixed/overflow on body: that carried the sticky sidebar away).
- Settings has three tabs (Appearance, Dashboard, Account); Appearance (`AppearanceStudio.js`) is a horizontal tab strip of visual pickers: Theme gallery, Colours (accent, sidebar colour via the `sidebar` pref, card finish via `cards`/`data-cards`), Style, Font, Charts, Layout (corners/text/motion/density/width) and Icons. User management (overview, roles & permissions, users) is its own top-level module at `/access`, with "Invite user" in the page header. All search boxes use `components/forms/SearchBox` (one clear button; the browser's own x is hidden globally in controls.css).
- Global motion: `styles/motion.css` (imported after cards.css) is the one place for shared curves (`--ease-out`, `--ease-spring`, `--ease-in-out`) and entrances (`m-rise`, `m-pop`, `m-sweep`, ...): rail item slide/pop on the active page, spring toggles, eased tabs/chips/segmented buttons, tab panels, menus/popovers/modals, pages, details, buttons, rows. `ThemeProvider` adds `html.is-restyling` for 450 ms after a theme/accent/sidebar change so colours cross-fade. Entrances use `backwards` fill (a held transform would contain fixed children). It also covers every button kind (lift, press, icon reaction, shine on primary/danger) and charts (donut segments, stacked and list bars, columns, lines, tooltips, legends: they grow in and answer hover; cinematic dashboard rules in dashEntrance.css still win on the first visit). Reduce motion (Settings or the device) removes it all. Put new transitions there, not in each sheet.
- Theme: ThemeProvider persists to localStorage; public/index.html applies it pre-paint (keep ids in sync with config/themes.js).
- Icons: always use `components/common/Icon` with an existing name (never import icon libraries elsewhere). It renders Phosphor icons in the user's chosen style (duotone default; regular/light/bold/solid) or our original "classic" set; style is saved with the theme (`config/icons.js`, Settings -> Appearance). A new icon needs an entry in BOTH the `PHOSPHOR` and `CLASSIC` maps (a test enforces parity).
- Charts are small SVG components (no chart library). KPIs/insights come from backend metrics (/dashboard/*); never compute totals from raw rows in the UI. Missing values render as a dash with a visible reason; completeness (complete/partial/insufficient_data/not_applicable) is shown via CompletenessBadge.
- Module pages are config-driven: features/<x>/ + features/resources/ResourcePage; forms come from GET /imports/templates. Dashboard filters live in the URL (useDashboardFilters). Presentations store sections + rolling period + filters; the player fetches live data as the viewer.
- Navigation is a left gradient rail (`components/navigation/SideNav.js`, `styles/rail.css`): full height, round icons stacked from the top with one `--rail-gap`, Settings as the last page link, and only the profile (account) icon pinned to the bottom; the active page curves out of the rail (inverted corners drawn in `--bg`, so keep the page background flat); the hamburger expands it to show labels (`company360.navExpanded`). Cinematic mode flips each card in from its own side, deals the stacked cards, draws the line, grows the bars. No extra requests; missing values stay dashes. Ember-only shell overrides (glass cards, dark rail, pill search on the left) live at the end of signature.css. `scripts/dev-stub.js` serves sample weekly trends and six projects for the local preview.
- Permissions in the UI: `useAuth().can('employees.edit')` (from `/me` `permissions`; sessions without a list fall back to the two original roles via `config/permissions.js`). Navigation items declare `permission`; pages use `RequirePermission`; `ResourcePage` gates Add/Edit/Delete/Approve separately; the spreadsheet follows `template.permissions` from `/imports/templates`. User management lives in `features/access/` (route `/access`, role matrix, users, overview); the Settings page keeps only personal, per-device preferences (Appearance: 29-theme gallery with dark/light filter, custom accent, corner style, text size, motion, icon style; Layout: density, page width, dashboard widgets; Backup & reset: export/import/reset of `company360.*` localStorage; Profile).

The local stub now does the same for `project_id`.
